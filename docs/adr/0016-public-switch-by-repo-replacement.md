# ADR-0016: 公开切换用「同名重建仓库」执行

- 状态：已确认
- 日期：2026-10-03
- 范围：`bingnnvjn/phanes` 从 private 切到 public 的执行方式（ADR-0012 决定 1 的落地步骤）

## 背景

工单 67 做完一次性历史清理（ADR-0014 的口径）后，本机历史里已经没有目标字符串。
但 `git push --force` 只让旧提交变成**不可达**，不等于删除。

2026-10-03 用已登录会话实测（只读）：旧提交与旧 blob 仍能按 SHA 取回——
`gh api .../git/commits/<旧 master SHA>`、`gh api .../git/blobs/<旧 blob SHA>` 都返回 200，
`git fetch origin <旧 SHA>` 也能成功。旧 blob 是历史版本里的工程 journal，含当时未脱敏的内容。

仓库当时仍是 private，未登录请求对任何 SHA 都返回 404。
所以泄漏不会现在发生，而会在**切 public 的那一刻**发生：任何人只要有旧 SHA 就能取回旧内容，
而仓库文本里恰好还留着这类旧 SHA 的指针。

沿用 2026-10-03 决策窗口 11 的「切现有仓库，不新建」会把这些对象一起带进公开范围。
该条前提不成立，必须改。

## 决策

1. **公开前先替换仓库**：删除 `bingnnvjn/phanes`，用**同名**重建为 private，再把本地
   `master` 推上去。旧仓库里的不可达对象随仓库删除而消失。URL 不变。
2. **重建后复测**：用重写前的旧 SHA（提交级与 blob 级）试取，两个都必须 404。
   测试用的 SHA 只记在仓库外复核文件里，不写进仓库。
3. **复测通过后才切 public**。切换后再用**未登录**会话复测同一批 SHA，同样必须 404；
   同时按工单 68 的匿名检查看首页、文件树、历史与 Actions 页面。
4. 只推 `master`；不建 tag、不建 release、不发布 APK。
5. **本决定取代** 2026-10-03 决策窗口 11 里「切现有仓库，不新建」那一条；该窗口的其余
   决策（保护开关、入口开关、只公开 `master`、切换需用户确认）不变。

## 考虑过的其他方案

- **保留现有仓库直接切换**：旧对象会随仓库进入公开可见范围；本机已实测它们仍可被取回；
  被否。
- **等 GitHub 自行 GC**：GitHub 不承诺删除不可达对象，也不提供时间表；被否。
- **请 GitHub Support 清除不可达对象**：可行，但慢且结果不保证；留作第 2 步复测失败时的
  后备手段，不作为首选。
- **新建另一个名字的仓库**：URL 变化会让本机 `origin`、文档里的克隆地址与既有链接失效；
  被否，采用同名重建。

## 后果

- 仓库元数据重置：创建时间、repo ID、设置、关注者。URL 不变，所以本机 `origin`
  （`https://github.com/bingnnvjn/phanes.git`）与文档里的克隆地址不用改。
- 工单 65 记录的 GitHub 端推送历史不再存在；本机历史、仓库外可恢复副本与工单记录不变。
- 删除是不可逆外部动作，执行前仍需用户确认（ADR-0012 决定 1）。用户已于 2026-10-03
  选定本方案。
- 本机与仓库外的副本不受影响；重建后应重跑 `scripts/public-release-gate.sh`。
