# ADR-0013: 应用身份冻结与项目改名

- 状态：已确认
- 日期：2026-10-01
- 范围：项目对外名称；Android 应用身份

## 背景

项目名 Fable 与同名产品存在混淆风险，新名 **Phanes** 已选定。改名的成本按层差异极大：

- **便宜**：文档、仓库名、App 显示名（来自单一 manifest 占位符）。
- **中等**：代码标识符（43 个 `Fable*` Kotlin 类、库名 `libfable-render.so` 等）。
- **昂贵**：Android 应用身份 `com.gph.fable`。`$PREFIX`
  `/data/data/com.gph.fable/files/usr` 由它派生，bootstrap 归档按该前缀构建（工单 06），
  `fable-repo` 的全部 `.deb` 亦按该前缀构建（ADR-0005），JNI 符号前缀同样绑定它。
  改动它意味着重建 bootstrap、重建整个包仓库、App 变为新身份（重装而非更新）、数据再迁一次。

## 决策

1. 项目对外名称改为 **Phanes**（原名 Fable / 寓言）。
2. **应用身份冻结**：`applicationId` = `com.gph.fable`，以及由它派生的 `$PREFIX`、
   JNI 符号前缀与签名身份，不随改名变化。词汇表新增"应用身份"一词。
3. 本次只改**对外可见层**：仓库名、README、新写文档、App 显示名。代码标识符的改名
   另行排期；不为它扩大本次范围。
4. 历史文档（ADR、工单）保留原文，不改写。改名事实在顶层说明中记录。
5. 为将来的代码标识符改名交付一份**改名清单**，标明各层及其必须同改的关联。

## 后果

- 仓库名与应用身份不一致：项目叫 Phanes，包名仍是 `com.gph.fable`。这是刻意选择，
  必须在文档中显式说明，否则会被后人误判为遗漏。
- 代码标识符与新名称不一致的状态会持续一段时间，直到改名清单被执行。
