# ADR-0012: 公开边界与构建输入

- 状态：已确认
- 日期：2026-10-01
- 范围：哪些内容进入公开仓库；构建输入的处理方式

## 背景

项目目标是一个完整的公开仓库。当前状态下有几类内容不适合公开：签名材料及其历史、
许可上不可再分发的第三方资产、真机运行数据、签名材料台账与私有远端台账。另有一批
构建输入体积超过版本库的合理范围（单个文件最大 136 MB，超过 GitHub 单文件硬上限）。

## 决策

1. 公开以**一个完整仓库**为单位。公开本身是独立的、不可逆的外部动作，执行前必须
   再次取得用户确认（承接 ADR-0010 第 5 条）。
2. 进入仓库的内容 = **产品 + 设计 + 可复现的结论**。**操作记录**不入库。操作记录包括
   真机运行数据（logcat、截图、性能采样）、一次性恢复副本、签名材料台账与私有远端台账。
   运行数据的分析结论以报告形式留在仓库内，原始数据不留。
3. **构建输入不入库**，由仓库内的获取脚本加 sha256 清单提供。构建输入包括 bootstrap
   归档、核心的预编译 `.a`、字体、预编译 `.so` 与工具链。
4. 许可上不可再分发的第三方资产不得入库，无论仓库当前是私有还是公开，例如
   Apple Color Emoji 字体。
5. 第三方来源与许可台账（`third-party-sources.md` 一类）属于公开内容，随仓库维护。

## 后果

- 公开仓库不含私钥历史、设备运行数据与不可再分发资产；这部分风险在公开前即已清除。
- 新设备恢复完整构建能力需要跑一次获取脚本，而不是 clone 即得全部二进制。
- 体积保持在版本库的合理范围，不需要 Git LFS。
