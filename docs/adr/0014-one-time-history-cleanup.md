# ADR-0014: 一次性历史清理（工单 63）

- 状态：已确认
- 日期：2026-10-02
- 范围：仓库历史；ADR-0011 决定 3 的冲突处置

## 背景

工单 62 合并五段历史后，ADR-0011 决定 3 记为"合并后不再重写历史"，fable-v1/62 的
结论写回也写明"历史从此不再重写：后续改名与裁剪在既有提交上追加"。工单 63 的验收
却要求操作记录与内部安全台账"不在索引**也不在历史**"。

2026-10-02 复核确认：这两类内容在**根仓库 Aug 8–20 段的历史里确实存在**——
`.scratch/fable-v1/migration/`（一次性迁移脚本与副本，14 个提交触及）与
`docs/security/{signing-material-inventory.md,rust-private-remotes.tsv,rust-public-boundary.md,rust-public-boundary.allowlist,rust-public-boundary.refs}`
（5 个提交触及）。两条要求不能同时满足，必须裁决。

## 决策

1. **一次性重写历史**：把上述两类路径从全部 ref 的每个提交树中移除。本决定由用户
   于 2026-10-02 明确授权。
2. 清理范围只限这两类路径。清理前后 `HEAD^{tree}` 必须逐字节相同（只改历史的
   可见内容，不改任何工作树内容）。
3. 清理前留仓库外可恢复副本（bundle）并记录 sha256；清理后做 fresh clone 复核。
4. **本决定是 ADR-0011 决定 3 后半句的一次性例外，不是普遍许可。** 此后再次重写
   历史仍需新的、明确的用户授权。

## 考虑过的其他方案

- **历史保持不动**：与工单 63 的公开边界要求冲突。公开是不可逆外部动作，公开后
  无法回收历史里的迁移脚本与内部台账；被否。
- **只删工作树、不碰历史**：等于把这两类内容留在公开历史里；被否。

## 后果

- 合并后的全部提交 SHA 变化（清理前 `master` = `287077e`，清理后 `7a8750a`）。
  ADR 与历史工单 Comments 里记录的旧 SHA——含 fable-v1/62 的四个合并提交与
  2026-10-01 五个 bundle 的校验点——只对清理前的副本有效。清理前副本：
  `<仓库外备份目录>/2026-10-02/<仓库外可恢复副本>`
  （sha256 `89a13575de0e4b433343c66a9b6e437d8c46434cea477e46d099ff968e041d6b`）。
- 一个只改迁移脚本的提交因此变空并被剔除（`fix(migration): storage permission fallbacks`），
  提交总数 247 → 246。
- 五段历史的合并结构不变：四个 merge 提交仍可在默认分支上追到，签名材料在历史中
  仍是零命中。
- 公开发布仍未发生，且仍需再次取得用户确认（ADR-0012 决定 1）。
