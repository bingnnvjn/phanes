# 换字体步骤（工单 22 更新机制）

适用：Apple Color Emoji 上游出新版（如 Emoji 18.0 / iOS 27.4）时按本文件升级。

## 1. 检查上游

```bash
scripts/check-emoji-upstream.sh   # 每周一次；输出当前版本 vs 上游最新 release
```

有新版（tag 含 apple）后，先确认：

- 新 release 的 ttc sha256 与版本串；
- 版本是否覆盖目标 Emoji 版本（18.0 预计 2026-09 Unicode 定稿，苹果约 2027 春推出）；
- 原版性：与 macOS 独立提取版交叉比对（参照 ADR-0007 的 ⚽ 0% 差异方法）。

## 2. 下载 + 更新溯源

```bash
scripts/fetch-emoji-fonts.sh     # 下载 -> 剥离 -> 校验 -> 写 assets
```

**常量同步点（ssot 闭环：改一处必须同步全部，否则构建/运行时校验不一致）：**

1. `scripts/fetch-emoji-fonts.sh` 顶部：`APPLE_URL` / `APPLE_TTC_SHA256` / `APPLE_TTF_SHA256` / `NOTO_SHA256`
2. `renderer/src/emoji.rs`：`APPLE_EXPECTED_SHA256` / `NOTO_EXPECTED_SHA256`
3. `android/.../FontAssets.java`：`APPLE_SHA256` / `NOTO_SHA256`
4. `scripts/check-emoji-upstream.sh`：`CURRENT`（当前版本串）
5. `renderer/src/main.rs`：Apple 版本串断言（`contains("21.4d3e1")`）
6. `docs/fonts/apple-emoji-provenance.md`：版本串、sha256、提取日期

## 3. 重建与验证

```bash
cd renderer && cargo run --release   # 离屏断言 ALL PASS（版本串断言同步更新）
cd android && export JAVA_HOME=/data/data/com.termux/files/usr/lib/jvm/java-25-openjdk && ./gradlew :app:assembleDebug
unzip -v <apk> | grep -E "AppleColorEmoji|NotoColorEmoji"   # 确认 noCompress（Stored）
```

## 4. 真机验收

按工单 22 真机项复测：40×10 与 80×24、字号 12/16/24/32/48、深浅主题、
对比图、深色边缘、RTL、选中/滚动无残影。

## 5. 收尾

- 更新 ADR-0007 的版本事实与重开条件；
- 工单 Comments 记录新版本验证数据；
- 新版本 sha256 固化进 fetch 脚本（老版本资产可保留到下次发布）。
