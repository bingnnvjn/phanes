## 本单最要紧的一条（工单 35 的教训）

**行为等价迁移必须逐对比较 Java 原件。** 编译器、单测、真机都不会报的静默漂移，全在逐行比对里才看得见。工单 35 就是这样抓出 5 个真错的。

工单 35 实际踩到的漂移类型（本单重点自查同类）：

- null 处理：`x?.toString()` 会不导出，Java `String.valueOf(x)` 导出字面量 `"null"`；`x ?: ""` 会吞掉 Java 的回写副作用
- 枚举取值：Kotlin `enum.name`（内建名）vs Java 自定义 `getName()`（契约值）
- 集合 API：`listOfNotNull` vs `Collections.singletonList`；`sortedWith`（不改写入参）vs `Collections.sort`（原地）
- 锁：Java `synchronized` 迁移后必须显式 `@Synchronized`
- 异常范围：catch 由 `IOException` 放宽为 `Exception` 会吞掉不该吞的错

本单额外风险点：`FablePluginUtils` 是 **RUN_COMMAND 外部入口本体**，错误回传、通知、PendingIntent 与策略校验都是对外可见行为，逐项对照原件，不要"顺手改良"。
