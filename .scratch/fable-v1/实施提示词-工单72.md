## 本单最要紧的一条（工单 35 的教训）

**行为等价迁移必须逐对比较 Java 原件。** 编译器、单测、真机都不会报的静默漂移，全在逐行比对里才看得见。工单 35 就是这样抓出 5 个真错的。

工单 35 实际踩到的漂移类型（本单重点自查同类）：

- 可见性收放：Java 包私有/`protected` 成员被 Kotlin 放宽为 `public` 是否改变了对外契约
- null 处理与默认值：`x ?: 默认值` 会吞掉 Java 的 NPE 或回写副作用
- 集合/字符串 API 的细微语义差（`sortedWith` vs 原地排序、区域相关大小写）
- 枚举自定义取值（Kotlin `enum.name` 与 `getName()` 不是一回事）
- 视图/手柄里被注释掉的边界判断（Java 里注释掉的 null 检查不要顺手恢复或删除）

本单额外风险点：`ExtraKeysView` 有 681 行且与输入法/手势强相关，`ReportActivity`/`TextIOActivity` 是对外可被外部应用唤醒的入口——manifest 入口身份与 intent extra 名必须逐字保值。
