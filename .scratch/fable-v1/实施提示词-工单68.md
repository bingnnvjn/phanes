## 环境快照（2026-10-03 核实）

- 仓库 `bingnnvjn/phanes`：当前 private，默认分支 `master`，唯一 ref `refs/heads/master`，无 tag、无 release
- `gh` 已登录 `bingnnvjn`，权限含 `repo`、`delete_repo`、`workflow`、`admin:org`；账号下没有组织
- 本机 `origin` = `https://github.com/bingnnvjn/phanes.git`
- 旧对象实测（2026-10-03，已登录，只读）：重写前的远端 `master` 提交与一个含未脱敏 journal
  的旧 blob 都还能按 SHA 取回；本机 `git fetch origin <旧 SHA>` 也成功。仓库仍 private，
  未登录请求全 404——泄漏会在切 public 那一刻发生。旧 SHA 记在仓库外复核文件，不写进仓库
- 重建：`gh repo delete bingnnvjn/phanes --yes` → `gh repo create bingnnvjn/phanes --private`
  → `git push -u origin master`（URL 不变，`origin` 不用改）
- 旧对象复测：`gh api repos/bingnnvjn/phanes/git/commits/<旧 SHA>`、
  `gh api repos/bingnnvjn/phanes/git/blobs/<旧 blob SHA>`、`git fetch origin <旧 SHA>`，
  三个都必须失败/404；切换后再用未登录会话复测同一批
- 切换：`gh repo edit bingnnvjn/phanes --visibility public --accept-visibility-change-consequences`
- 核对：`gh api repos/bingnnvjn/phanes/git/refs`、`gh api repos/bingnnvjn/phanes/tags`、`gh repo view bingnnvjn/phanes --json visibility,defaultBranchRef`
- 三个既有私有远端 `<私有远端1>`、`<私有远端2>`、`<私有远端3>` 本轮不动
- `bingnnvjn/fable-bootstrap` 已是 public，本轮不动
- 网络：GitHub 直连偶发超时；`git -c http.version=HTTP/1.1` 重试；直连慢时用 `https://ghfast.top/` 前缀
