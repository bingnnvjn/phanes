## 工单任务

1. **替换 bootstrap**：把 `fable-app/app/src/main/cpp/bootstrap-aarch64.zip` 换成工单 06 的产物。本地已有副本 `$HOME/.codex_tmp/fable06/bootstrap-aarch64.zip`（sha256 `d9fc5f96691afdeb83ecffc0e9571a7e88cf127d775beefc53d9a0e353e0a601`，已验证）；也可从 Release 下载（GitHub 直连慢，用 `https://ghfast.top/https://github.com/...` 前缀加速，URL 见工单 06 Comments）。替换后核验 sha256。
2. **重建**：`cd fable-app && export JAVA_HOME=/data/data/com.termux/files/usr/lib/jvm/java-17-openjdk && ./gradlew :app:assembleDebug`（zip 经 termux-bootstrap-zip.S 嵌入 libtermux-bootstrap.so，构建会自动重编原生库）。
3. **产物校验**：
   - aapt2 badging：包名 `com.gph.fable`；apksigner：<签名证书主体>；APK 含 `lib/arm64-v8a/libtermux-bootstrap.so` 等 3 个 .so
   - **内嵌 bootstrap 抽查**：从 APK 抽出 `libtermux-bootstrap.so`，找到内嵌 zip（PK 头），解出 `etc/termux/bootstrap/termux-bootstrap-second-stage.sh`，确认 shebang 与 `TERMUX_PREFIX` 为 `/data/data/com.gph.fable`，且 `bin/bash`/`bin/dpkg` 无 `com.termux` 字符串
4. **交付安装**：APK 复制一份到 `/storage/emulated/0/Download/`（用户从那里安装，安装后自动删包，原件留在构建目录）。真机验收若环境做不了，把 APK 路径与验收步骤写清楚交回，由用户配合：打开 Fable → 直接进终端 → `echo ok`/`pwd` → `$PREFIX` 应为 `/data/data/com.gph.fable/files/usr` → `uname -m` 应为 `aarch64` → 无 Bootstrap Error。
5. **写回工单 07 `## Comments`**：APK 路径、内嵌 bootstrap 校验结果、装机验收结论；关联说明工单 01 的两个待验收项（装到手机、打开即终端）是否随之达成。
