### 坑与解法

1. **删掉仓库里的 aapt2 覆盖后本机仍能构建**：因为覆盖早已写在用户级
   `~/.gradle/gradle.properties`。这正是要写进文档的替代方式；x86_64 电脑不写这一行。
   验证命令见上面"用户级 aapt2 生效"。反过来说，这台设备上"删了也能跑"不能证明
   "不需要覆盖"，文档里明确区分了两种宿主。
2. **`build-and-verify.sh` 的 shebang 与 JDK 路径都是本机绝对路径**（`#!/data/data/com.termux/…/bash`、
   `java-17-openjdk`）：新设备连解释器都找不到。改成 `#!/usr/bin/env bash` + 环境解析，
   并把工具解析顺序设为 `环境变量 → PATH → SDK build-tools`，因为 aarch64 上 SDK 自带的 aapt2
   是 x86_64，先取 PATH 上的原生 aapt2 才跑得动。
3. **上游 `android/README.md` 会把新设备带偏**：标题是 Termux application，徽章指向
   upstream Actions，安装章节讲 F-Droid/GitHub 上的 Termux。改写成本目录说明并删除
   `android/docs/en/index.md`（指向 termux 文档站的占位页）。`android/docs/signing.md` 是本项目的，
   保留。
4. **App 显示名落地牵动一个身份测试**：`FablePackageIdentityTest` 原先把
   `TERMUX_APP_NAME == "Fable"` 当成"永久身份"锁死（工单 01 写的）。ADR-0013 把显示名归入
   对外可见层、身份只认 `applicationId` 及其派生物，所以改了三处显示名来源
   （Gradle 占位符、`strings.xml` 实体、`TermuxConstants`）并把测试断言改为 Phanes，
   注释写清"显示名不是身份"。身份相关断言（`applicationId`、数据目录、权限、authority）一字未动，
   单测通过。
5. **仍指向 termux 上游的只剩运行期链接与一份构建输入**：`TermuxConstants` 的
   wiki/issues URL 让 App 内"Report Issue"指向 `termux/termux-app`；`downloadBootstraps`
   对 arm/i686/x86_64 三份仍取官方 termux-packages Release（aarch64 取自有 Release）。
   两者都不是"仓库自动化"，本单按红线不扩大范围，记录在此待后续决定（改 Report Issue 目标
   属产品决定，改 bootstrap 来源要重建归档）。
6. **Rust 测试与 example 里写死 Termux 路径**：`session/tests/*.rs`（bash、HOME、PREFIX）、
   `renderer/examples/*.rs` 与 `renderer/src/main.rs`（DejaVu 字体路径）。它们是本机真机测试
   与切片程序，不是构建 APK 的必需项；x86_64 电脑跑这些需要另开可配置项，本单不动，记入
   已知项。
7. **`android/build.gradle` 仍保留 `maven { url = "https://jitpack.io" }`**：这是依赖仓库声明
   而不是发布或自动化，删掉有过期风险；只删了 `jitpack.yml` 与触发工作流。
