# 69 — 核心读取缝：把读核心的代码收成一份

**What to build:** 渲染器里"从核心读数据"的能力现在散成 9 份：渲染器本体一份、头部验收程序一份、外加 7 个没有任何地方引用、也不做断言的诊断程序。这 9 份已经各自漂移：同一段不安全取值有 4 种写法，出错处理有两种不兼容策略，验收程序还有自己的一份格子类型。本单把读取能力从渲染线程内部搬成一个独立 module，由两个对象组成：一个持核心连接，一个持渲染状态；渲染器本体只保留 GPU 与渲染线程，改持这两个对象；头部验收程序与其余示例程序都改用这一份实现，7 个死诊断程序删除。

目标不只是少抄几行。三件事必须一起到位：读取的 unsafe 推导只有一处；"读之前必须先更新渲染状态"这条核心规矩收进类型，调用方漏不掉；窄查询（取一个词、取一段文本）不必为了读一行去分配整屏快照。

**Blocked by:** None
Status: 待开工

## 验收清单

- [ ] 读核心的能力只有一份实现；渲染器本体与头部验收程序都不再自带读取逻辑，也不再有各自的格子类型
- [ ] 读取能力可以在不启动渲染线程、不需要 GPU 的情况下使用
- [ ] 示例程序里 7 个无引用、无断言的诊断程序删除；示例程序目录下不再有抄写的读取辅助函数
- [ ] module 顶部写明两条：为什么分成两个对象、"读之前必须先更新渲染状态"；并写明这是业务代码唯一入口，不直接调 ffi
- [ ] 出错语义统一：会改变结果的调用返回错误；单字段读取失败按内部不变量处理（测试期断言）；module 自己不写日志，由调用方决定策略
- [ ] 快照与格子等数据类型随读取能力一起迁移，旧 import 路径不留
- [ ] 取词边界、去行尾空白、续行判断抽成不接触核心的纯函数，并带测试
- [ ] 渲染器本体行为不变：真机上的绘制、滚动、选择、字号、配色、标题/铃铛/模式查询全部照旧
- [ ] 搬走以后原位置不留同名转发方法
- [ ] 三条 Rust 门禁通过；三个 crate 的 `cargo check --all-targets` 通过；秘密扫描 0 命中
- [ ] 不改应用身份与对外可见层；构建输入不入库

## Comments

2026-10-04 建单。来源是 `/improve-codebase-architecture` 体检（方向映射表登记「架构体检 C1 · 核心读取缝」，`spec.md` 决策 16）。

体检过程值得记一句，因为它改了结论。前两轮扫描给出的判断是"`cell_text` 抄了 9 份"，据此提了四个方案：A 只搬知识、B 模块接管整条核心连接、C 两段式、D 照核心自己的分界切两个类型。第三轮把示例程序清单和 `libghostty` 头文件的线程规则查清以后，两件事变了：

1. 真正的重复单位不是那 5 个小函数，而是"建终端 → 建渲染状态 → 喂字节 → update → 读 → 释放"这整段，约 40 行，出现 19 处（`renderer/src/main.rs` 一个文件里就有 4 处）。A/B/C/D 都只处理小函数，这段全留着。
2. 读取逻辑其实已经写好，就在 `RendererCore` 上（`title`、`consume_title_changed`、`consume_bell`、十个 `mode_*`、`terminal_size_t`、`scrollback_rows`、`total_rows`、`text`、`word_bounds_at`、`word_at`、`transcript_text`，`renderer/src/render_android.rs:3871-4246`），只是私有、拿不到，所以外面的程序只好抄。

所以最终方案是"搬现成的"，不是"新写"。这比 D 少写一遍已跑通的代码，也比 B 小得多。

决策窗口 12 定案的四件事：

1. 命名：`renderer/src/core.rs`；`Terminal` 持核心连接，`Screen` 持渲染状态；用短名，不加 `Core` 前缀。
2. 出错：会改变结果的调用（open / feed / resize / scroll / update / snapshot）返回 `Result`；单字段读取（text / word_at / word_bounds_at / title / mode_*）返回普通值，失败按内部不变量处理，`debug_assert` 加日志。module 自己不写日志。
3. 类型：`Rgb`、`Palette`、`Cell`、`Snapshot`、`OverlayRange` 随读取能力搬进新 module，不留旧 import 路径（现在它们都是 `render_android.rs` 的 `pub` 类型，被 4 个示例程序和 `jni.rs` 引用）。
4. 测试：只抽纯逻辑加测试；不在本单解决"renderer 测试在 CI 上被跳过"的问题，另单。

删除 7 个诊断程序的判据（2026-10-04 核实，全仓 grep 无引用）：`dbg_noto`（16 行）、`diag_2027_flags`（110）、`diag_cells_both`（127）、`diag_core_split`（113）、`diag_emoji22`（74）、`diag_width`（266）、`scroll_delta_check`（119），合计 825 行。安全性依据三条：6 个是纯打印、没有断言；`scroll_delta_check` 的结论已被头部验收程序里的滚动验证覆盖；工单 22 那几个诊断的结论已被渲染器内 5 个具名测试覆盖（`emoji_layout_not_overlapping`、`emoji_canvas_em_box_uniform_after_ticket22`、`wide_glyph_column_position_no_overlap_ticket22`、`color_atlas_unified_cell_upgrade_ticket22`、`overlay_cursor_wide_span_ticket22`）。另与 ADR-0012 一致：一次性诊断程序属操作记录，不入库。

体检报告写在 OS 临时目录、不入库（ADR-0012）。本 Comments 是这套设计的仓库内唯一记录。
