# 42 — 外部文件路径边界统一加固

**What to build:** 为外部 Intent、DocumentsProvider 和文件分享 Provider 建立统一的 canonical containment 模块；接收文件名不能逃出接收目录，document ID 不能逃出 Fable `$HOME`，对外文件 URI 只能落在允许根目录；修复输入流生命周期和重复 Intent 处理。

**Blocked by:** None
Status: 已完成

## 验收清单

- [x] canonical containment 对根目录、正常子文件、`../`、相邻前缀目录和 symlink escape 有自动化测试
- [x] 接收文件名拒绝绝对路径、目录分隔符、`.`/`..` 和 canonical escape，不覆盖目录外文件
- [x] DocumentsProvider 的查询、创建、删除、打开和 child 判定都限制在 Fable `$HOME`
- [x] FableOpenReceiver Provider 使用统一允许根目录校验，不再直接做字符串前缀判断
- [x] FileReceiver Intent 每次只处理一次，输入流在用户确认时打开并可靠关闭
- [x] 相关单测、app 编译和既有测试基线不劣化

## Comments

2026-08-12 完成。

- 验证数据：`SafeFilePathsTest` 5/5 通过；覆盖根目录、正常子路径、`../`、相邻前缀、symlink escape、危险叶子名和同名文件不覆盖。`./gradlew :termux-shared:testDebugUnitTest --tests com.gph.fable.shared.file.SafeFilePathsTest :app:compileDebugJavaWithJavac` 成功（44 秒，44 tasks）；此前同轮全量 `:termux-shared:testDebugUnitTest --rerun-tasks :app:compileDebugJavaWithJavac` 成功（1 分 16 秒，44 tasks）。
- 坑与解法：单纯 canonical 校验后再用普通 `FileOutputStream` 仍会覆盖同名文件；改为共享模块先以 `createNewFile()` 原子占位，冲突明确报错，写入失败删除本次不完整文件。Robolectric 4.8.1 在 JDK 25 下的既有 `FileReceiverActivityTest` 类加载失败未扩大，本工单以纯 JVM 路径缝测试和 app 编译验收。
- 结论写回：外部文件入口统一依赖 `SafeFilePaths`；后续 Kotlin 迁移保留该模块接口，不在 Activity、DocumentsProvider 或 Provider 内重新引入字符串前缀路径判断。
