# 65 — 验证、扫描与私有推送

**What to build:** 在一份全新 clone 上证明这个仓库可重建：跑秘密扫描与 Rust 门禁，按仓库文档在手机侧走一遍构建。都通过后创建私有仓库 phanes 并推送。公开不在本单范围。

**Blocked by:** fable-v1/64
Status: 待开工

## 验收清单

- [ ] fresh clone（从本地路径克隆，不带工作区未提交内容）后，未提交改动与未跟踪文件均为零
- [ ] 秘密扫描覆盖工作树、索引、全部 ref、reflog、可达与不可达对象；签名材料路径、token 与私钥标记零命中；输出只留 PASS/FAIL 与摘要
- [ ] 三个 Rust crate 的格式化、严格 lint、全目标测试、rustdoc、锁定依赖检查通过，供应链门禁通过
- [ ] 应用侧按仓库文档走一遍构建：不靠文档以外的口头知识即可配好环境并产出 APK；包名、签名与原生库清单与文档一致
- [ ] 构建输入按文档获取，每样校验 sha256 与来源表一致
- [ ] 任一项不通过则停在本单的验证阶段，不推送；不完整的结果不得写成可推送
- [ ] 全部通过后创建私有仓库 phanes，记录所有权、可见性与默认分支
- [ ] 推送为默认分支一次推送，不带 tag、不带其他 ref、不带 `--force`
- [ ] 推送后复核远端：ref、源码树与历史同本地已审计状态一致；树上无签名材料、无操作记录、无内部台账
- [ ] 仓库可见性保持 private；本单不改可见性、不建 release、不建 tag
- [ ] 三个既有私有远端保持原样，其去留在本单之后再单独决定

## Comments

2026-10-01 建单。验证与推送绑在一张工单里，是为了让"推上去"带前置条件：没有 fresh clone 与扫描证据，就没有推送动作。

三个既有远端这次只当异地副本留着；新仓库验证通过前不动它们。
