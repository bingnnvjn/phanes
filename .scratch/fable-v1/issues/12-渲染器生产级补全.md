**三个根因（都已修）**：

1. WGSL 写 `let layer = if (...) {...} else {...}`（if 表达式），naga 解析失败 → `ensure_pipeline` 报错 → 每帧只清屏。改为 if 语句赋值。
2. `align_slot` 用位掩码 `& !2303` 对齐 2304，但 2304 非 2 的幂，掩码实际对齐到 512，所有行/overlay 字节偏移错位：80 列时 overlay 偏移 2490368（非 36 倍数），顶点索引 69176 从错位字节画；设备 90 列时从第 1 行起全部错位 → 文字/光标全不可见。改为 `v + 2304 - v % 2304`。
3. 官方约定：`ghostty_render_state_update` **只更新不清 dirty**，调用方渲染后必须自己 `set(DIRTY_FALSE)` + 逐行 `row_set(DIRTY=false)`。此前从未 reset，每次 update 恒为 FULL、增量从未生效。补 `ghostty_render_state_set` / `ghostty_render_state_row_set` FFI，成功 present 后 reset。

**② 彩色 emoji 图集**

- 灰度/彩色双图集：灰度沿用 fontdue（2048x2048/32 格），新增彩色图集（2048x2048/64 格），GPU 用 `texture_2d_array` 双层上传，shader 按 mode（1=灰度、2=彩色）分层采样。
- 彩色字形来源：`emoji.rs` 用 ttf-parser 从 CBDT/CBLC 位图字体提取内嵌 PNG + png 解码为 RGBA。
- **坑（重要）**：本机 `/system/fonts/NotoColorEmoji.ttf` 是 COLRv1 矢量（无 CBDT/sbix），ttf-parser 提不出位图；改为内嵌 googlefonts/noto-emoji `v2017-03-10-color-emoji-binary` 的 CBDT 位图版（5.3MB，OFL-1.1，`assets/NotoColorEmoji.ttf` + 许可说明）。
- **坑**：CBDT 内嵌 PNG 是 Indexed + tRNS，png 解码必须 `normalize_to_color8() | ALPHA`，否则 `next_frame` 后颜色类型仍是 Indexed 而无法转换。

**④ 独立渲染线程 + mailbox（demand lock 思路）**

- `Renderer` 改为句柄：`RendererCore` 移到专属线程（每会话一个 `fable-render-thread`），JNI 全部变 mailbox 非阻塞（std mpsc）；核心/图集/wgpu 只在渲染线程访问，天然无锁竞争。
- demand lock 对应：渲染线程独占核心状态，I/O（PTY reader → Kotlin 主线程 → mailbox）只投递不抢锁；写入与渲染消息按序消费，快速输出不丢帧。
- 生命周期：`Renderer::drop` 投 Quit + join；GpuRuntime Drop 释放 ANativeWindow；`renderer_thread_check` 验证 200 次 write+render 投递 0ms、线程启动/退出干净。
- 真机验收待用户：UI 线程不再执行渲染，理论无 ANR/掉帧。
