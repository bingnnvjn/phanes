2. 踩过的坑与解法：
   - 工单 58 创建 private remote 后，旧的“任意 remote 均失败”规则已不再适用。
     新增机器可读的 private-remote 台账，边界门禁现要求 remote 名称、fetch URL
     和 push URL 精确匹配；台账不替代 GitHub 所有权、权限或可见性的人工复核。
   - 仅从工作树移走 `<上游测试签名材料>` 会掩盖它仍在索引和历史的事实。总闸门
     现对索引、refs/reflog 中的已知 JKS 路径 fail-closed。
   - gitleaks 原先只扫描工作树、可达 refs 和 reflog；现逐个扫描不可达 blob。
     根仓库发现阻断时不输出 blob、路径推测或匹配文本，避免二次泄露。

3. 结论写回：
   - 工单 57 的自动化边界、工具固定、许可证/供应链和 crate 发布边界可重复复核；
