# 62 — 备份、签名材料历史清理与五仓合并

**What to build:** 把当前五个 git 仓库收敛成一个。先给每个仓库留一份可恢复的 bundle 备份；把签名材料从应用仓库的全部历史里移除，并在 fresh clone 中复核；再以根仓库为基底，用 subtree 把四段历史并入角色目录。合并过程中不丢工作区里任何未提交的内容。本单之后不再重写历史。

**Blocked by:** None
Status: 待开工

## 验收清单

- [ ] 五个仓库各产出一份 git bundle，记录路径、大小与 sha256；bundle 一律放仓库外受限目录，不进入任何仓库
- [ ] 应用仓库的两处签名材料（签名材料台账记录的两个 keystore）已从全部 branch、tag、reflog 与不可达对象中移除
- [ ] 复核签名配置与发布诊断日志从未进入应用仓库历史；已进入的按同一流程处理
- [ ] 历史清理只作用于应用仓库的副本，其余四个仓库的历史未被改写
- [ ] 清理后在 fresh clone 上复核：签名材料路径在索引、历史、tag、reflog 中零命中
- [ ] 应用仓库的原 Termux upstream 远端保留为只读参照；全程未向该上游推送任何内容
- [ ] 根仓库对四个源目录的忽略规则已解除，合并后的角色目录可被正常跟踪
- [ ] 四段历史以 subtree 合入对应角色目录，各仓库原有提交在合并后的默认分支上可达
- [ ] 四个源仓库工作区里的未提交改动已按其归属提交或并入，内容与合并前一致
- [ ] 根仓库尚未提交的设计文档（ADR-0011/0012/0013、词汇表、构建输入来源表）与其工作区改动已提交，合并后不丢
- [ ] 根仓库那个不在任何分支上的大 blob 已按处置要求清理，本地对象库体积明显下降；可推送内容不受影响
- [ ] 合并结果满足后续步骤的前提：默认分支上五个角色目录齐全，一次 `git log` 能同时追到五段历史
- [ ] 记录本单对既有工单 fable-v1/55、fable-v1/59、fable-v1/51 的影响（ADR-0011 作废 ADR-0010 第 1、3 条，这三张工单的仓库拓扑前提已变）；在它们的 Comments 追加说明并给 Status 加挂起原因

## Comments

2026-10-01 建单。工单 55 的公开审计前提是"三个 Rust crate 各自独立公开"，ADR-0011 改为单仓库后，那套拓扑作废，本单是新的拓扑定型处。

风险最集中的一段在这里：历史清理与 subtree 合并都会改变仓库拓扑，所以放在一张工单里一次做完、一次验收，避免"清理到一半"的中间态被后面的工单当成可推送输入。
