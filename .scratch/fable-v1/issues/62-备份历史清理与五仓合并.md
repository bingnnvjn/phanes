# 62 — 备份、签名材料历史清理与五仓合并

**What to build:** 把当前五个 git 仓库收敛成一个。先给每个仓库留一份可恢复的 bundle 备份；把签名材料从应用仓库的全部历史里移除，并在 fresh clone 中复核；再以根仓库为基底，用 subtree 把四段历史并入角色目录。合并过程中不丢工作区里任何未提交的内容。本单之后不再重写历史。

**Blocked by:** None
Status: 已完成

### 踩过的坑

- `git bundle verify` 必须在对应仓库目录内执行；在 bundles 目录里跑会因"need a repository"返回 FAIL，误判成坏备份。
- `git subtree add` 的前置检查是 `git diff-index HEAD`，未暂存的改动会让它报
  `fatal: working tree has modifications.  Cannot add.`。本次 `.gitignore` 改动没 `git add` 就提交，
  于是第一次 add 被拦下；补进同一提交（amend）后通过。做法教训：subtree 前先跑 `git diff-index HEAD` 确认干净。
- `git filter-repo` 会顺手删掉 `origin` 远端并清空 reflog。对清理副本来说正好，等于自带"不会误推"。
- 合并后 `renderer/` 与 `libghostty/` 的兄弟关系被打破了一次：`renderer/build.rs` 原本链接
  `../spike-libghostty/lib/arm64-v8a`，`src/emoji.rs` 与 `src/bin/diag_sbix.rs` 原本指向 `../fable-app/...`。
  在合并后的仓库里改了这几条相对路径（提交 `a7bb62d`），只动路径与注释，不动包名与 unsafe 合约。
- 根仓库 `scripts/*.sh`（`rust-quality-gate.sh`、`public-release-gate.sh`、`fetch-emoji-fonts.sh`、
  `build-session-lib.sh`）与部分文档仍写旧目录名，合并后按旧路径跑不通。这属于工单 63 的"引用旧目录名的构建脚本、闸门脚本同步更新"，本单未越界处理。
- `libghostty/` 目前只跟踪 `README.md`：`.a`、头文件、Nerd Font、JNI 探针与 `.so` 都留在索引外，符合 ADR-0012。
  63 需要复核这个目录到底该跟踪到哪一层。
- 四个原始工作树仍在仓库目录内（`fable-app` 2.3G、`spike-render` 4.5G、`spike-session` 834M、`fable-boo` 101M），
  解除忽略后它们以未跟踪目录出现在 `git status`。它们已被 bundle 覆盖，但本单按"不删用户数据"处理，留待 63 裁剪。
  三者的私有远端与工作树都没有被动过。
