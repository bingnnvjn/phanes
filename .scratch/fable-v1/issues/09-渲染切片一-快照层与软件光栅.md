# 09 — 渲染切片一：快照层 + 软件光栅（核心 → 渲染状态 → 像素帧）

**What to build:** 按 ADR-0004，在纯 Termux 环境下跑通"libghostty-vt → RenderState 迭代器 → 终端快照 → 软件光栅 → 像素帧（PNG）"，验证渲染数据层正确。不接 GPU、不进 APK；画法层暂用 CPU 软件光栅（借 betamax 思路），快照层与后续 GPU 版完全共用。

**Blocked by:** None（前置：rustc 修复、ADR-0004 已定案）。

Status: 已完成

## 目标

1. 建 Rust crate（`spike-render/` 或 `render-slice/`），链接已验证的 libghostty-vt（expo 预编译 .a，arm64），复用工单 08 的 TLS/对齐处理。
2. 快照层：从核心读渲染状态 → 终端快照结构（脏行、行文本、样式 run、光标、配色板、滚动信息）——**正文走 RowIterator/CellIterator**（官方/betamax 路径，不用 Shellow 的逐格 grid_ref）。
3. 软件光栅：把快照画成 RGBA 像素帧（背景矩形 + 字形 + 光标），输出 PNG 供肉眼/程序化验收。
4. 验收集：SGR 颜色/粗斜体、中文宽字符、滚动缓冲、resize 重排、光标位置——与预期输出逐项比对。

## 技术决策（待切片内确认）

- FFI 路线二选一（切片内试通即定）：
  - A. 手写/生成 FFI 链接现有 expo .a（复用已验证核心，最快；需处理 TLS 对齐坑）
  - B. 用 libghostty-rs crate（安全 API，pin ghostty ab0b9da9，需 Zig 0.16 自建核心；Termux 内构建慢、需重验坑）
- 软件光栅组件：cosmic-text + swash（betamax 同款）或 fontdue（Shellow 同款）；PNG 写出用 image crate。

- **语义确认**：RenderState RowIterator 只暴露当前 viewport 的 rows；历史行须先 `ghostty_terminal_scroll_viewport` 再 `ghostty_render_state_update`。这正是后续渲染器滚动条/触摸滚动的正确路径。
