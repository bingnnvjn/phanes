**2. 坑与解法**

- **裸形式漏网**：同一类名字在历史里还有不带 `.sh`/`.py` 后缀、以及不带日期的写法
  （占位符见上文映射表）。首轮 `--replace-text` 只匹配带后缀形式，于是历史 blob 里仍有
  6 处。解法：对全库对象做一次 `git cat-file --batch-all-objects` 扫描，按类别枚举
  变体，补规则后再跑，直到零命中。
- **大小写变体漏网**：证书指纹在历史里还有全大写写法（应用常量里），而首轮规则只写了
  小写。解法：改用大小写不敏感的 `regex:` 规则覆盖整段十六进制，再全局复扫。
- **替换规则会误伤公开仓库名**：三个私有远端之一的短名，是公开包仓库地址（必须保留）的
  字符串前缀。解法：用 `regex:` + 负向前瞻，只在该前缀后面不是包仓库后缀时替换。
- **功能性引用不能删**：`scripts/public-release-gate.sh` 与 `android/test-signing-config.sh`
  原先按文件名点名两个 keystore。解法不是改名混淆，而是把检查泛化成"任何被跟踪的
  `.jks`/`.keystore` 或历史里的签名材料路径都失败"（等价且更强），字面量随之消失。
- **CI 在非 Termux 宿主必挂**：`session` 两个验收切片硬编码 `$PREFIX/bin/bash` 与
  Termux home，GitHub-hosted runner 上 `cargo test` 会失败。解法：改成运行时从
  `HOME`/`PREFIX`/`PATH`/`TMPDIR` 推导（Termux 走 `$PREFIX/bin/bash`，其它宿主回落到
  PATH 上的 bash），断言同步用推导值；本机重跑 `session` 11 项全绿。顺带清掉了源码里
  最后两处家目录字面量。
- **`filter-repo` 会删 `origin`**：这是它的既有行为（防误推）。解法：重写后重新
  `git remote add origin`，再 force push。
- **`.git/filter-repo/already_ran` 残留**：上次清理（工单 63）的标记还在，filter-repo 会问
  是否续跑。解法：显式回答 `N`，当新一次重写处理。

**3. 结论写回（对后续工单/决策的影响）**

- 工单 68 第一条核对现在成立：远端 `master` = 本地 `HEAD`（取当前值，见 `git ls-remote`
  与 `git log -1`），闸门摘要对应这个 HEAD。
  **但有一条硬提醒**：force push 只让旧提交不可达，GitHub 仍可能按完整 SHA 直接提供旧对象。
  2026-10-03 用已登录会话实测确认：重写前的旧 master 提交与一个含未脱敏 journal 的旧 blob
  都能取回（`git fetch origin <旧 SHA>` 成功）。因此用户同日裁定：**先同名重建仓库，再切
  public**（见 ADR-0016）；本单的"重写后零命中"只覆盖仓库自身，不覆盖 GitHub 上残留的旧对象。
  工单 68 必须先做重建与旧 SHA 404 复测，再切可见性。
- 历史重写的授权是一次性的：本次依据 2026-10-03 决策窗口授权（ADR-0014 决定 4 的口径），
  此后再次重写历史仍需新的、明确的用户授权。
- `.scratch/` 现在会被秘密扫描覆盖，且已是脱敏内容；后续新增工单/报告不得再写个人环境
  细节（备份目录、keystore 细节、私有远端地址、家目录绝对路径、包清单、服务脚本名、
  设备与 ROM 版本）。
- 三个 crate 的 `CONTRIBUTING.md`/`SECURITY.md` 已不存在，`scripts/public-release-gate.sh`
  的必查清单同步改动，规则去处是 `docs/agents/rust-quality.md` 与
  `docs/agents/rust-supply-chain.md`；根 `SECURITY.md` 承担漏洞报告入口。
- 本单未切可见性、未建 tag/release、未动三个既有私有远端；切换到 public 及 required
  checks 配置仍是工单 68 的事，且执行前必须再次取得用户确认（ADR-0012 决定 1）。
