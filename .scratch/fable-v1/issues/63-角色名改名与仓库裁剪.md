### 坑与解法

1. **移动 target 目录而不是重建**：`git subtree` 合并只带源码，四段历史的 `target/` 缓存留在原工作树里。先把 `spike-render/target`→`renderer/target` 等三个目录在文件系统内改名（同一分区，瞬时），再删原工作树；cargo 复用依赖产物，renderer（wgpu + FreeType）冷编译避免。
2. **应用侧构建输入全在旧工作树里**：`app/src/main/assets/fonts/`、`app/src/main/cpp/bootstrap-*.zip`、`app/src/main/jniLibs/arm64-v8a/*.so`、`local.properties` 都是被忽略的构建输入，合并后的 `android/` 没有它们。构建前把它们移进 `android/`（仍不入库）。
3. **bootstrap 下载被 GitHub 直连卡死**：`downloadBootstraps` 发现 `bootstrap-arm.zip` 哈希不符就删除并直连 GitHub，`SocketException: Connection timed out`（`curl` 直连 `000`，`ghfast.top` 前缀 `200`）。解法：用 `https://ghfast.top/` 前缀手工取回 arm/i686/x86_64 三份官方 bootstrap 到 `android/app/src/main/cpp/`，sha256 与 `app/build.gradle` 里的期望值逐一核对通过；随后构建不再走网络。
4. **`supply-chain-exceptions.toml` 的两项公告例外已过期**（`RUSTSEC-2026-0192` ttf-parser、`RUSTSEC-2026-0206` rustybuzz，`review-by = 2026-09-15`，今天 2026-10-02）。这是工单 52 留下的既有阻断，不是本单引入；延长例外属于安全决策（文档要求"ledger 与工单同改"），本单**没有**擅自延期，留给工单 51/65 处理。
5. **路径型依赖摘要包含路径前缀**：`rust-supply-chain-gate.sh` 的 `path_tree_sha256` 把 `find` 输出的相对路径一起哈希，`spike-session/vendor/portable-pty` → `session/vendor/portable-pty` 会让摘要"变化"。先 `diff -rq` 证明树内容与改名前的副本逐字节一致，再更新 `content-sha256` 并续记 `reviewed-on = 2026-10-02`。
6. **闸门脚本的三仓假设**：`scripts/public-release-gate.sh` 原来要求三个 crate 各自是独立 Git 顶层、校验 `fable-app` 的 Termux 上游，这些都随 ADR-0011 作废。改为单仓库形态：crate 变成角色目录、扫描只在根仓库跑、`libfable-*` 与签名边界改为按冻结身份检查；`has_forbidden_tracked_path` 也从"在某 crate 目录里跑 `git ls-files`"改成"对根仓库按 crate 路径过滤"。
7. **公开发布闸门首跑出现一次瞬态失败**：同一命令第二次跑 48 checks / 1 failure（只剩供应链项），单独复跑 `rust-quality-gate.sh` 也是 15/15；判定为首次运行时的偶发失败（同期有 cargo/gitleaks 资源争用），记录在案以免被当成已修。
