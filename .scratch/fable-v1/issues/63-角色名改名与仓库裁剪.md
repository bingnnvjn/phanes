# 63 — 角色名改名与仓库裁剪

**What to build:** 把"五段历史拼在一起"的仓库变成自洽的单一仓库。目录与包名改成角色名；把不入库的东西清出去：构建输入、操作记录、内部安全台账；忽略规则统一成一套；原安全目录按 ADR-0011 改为发布目录。产品名标识符这次不动。

**Blocked by:** fable-v1/62
Status: 待开工

## 验收清单

- [ ] 五个角色目录定型：应用、渲染器、会话层、动画程序、终端核心资产都用角色名，目录名中不含产品名，也不含 `spike-` 前缀
- [ ] 三个 Rust crate 的包名改为角色名；引用这些包名与旧目录名的构建脚本、闸门脚本与工作流同步更新，更新后脚本可运行
- [ ] 应用侧模块目录按 ADR-0011 改用角色名，Gradle 模块引用与文档同步更新
- [ ] 本次不改产品名标识符：`applicationId`、派生的 `$PREFIX`、JNI 符号前缀、签名身份、两个 `libfable-*.so` 文件名、`Fable*` 类名保持原样；未改项逐条进改名清单（工单 64 交付）
- [ ] 构建输入不在索引也不在历史：bootstrap 归档、Apple 彩色字体、预编译 `.a`、预编译 `.so`、工具链压缩包、Nerd Font 包；仓库内的 OFL 字体按构建输入来源表保留
- [ ] 操作记录不在索引也不在历史：真机运行数据与基线原始数据、诊断现场、一次性恢复副本、构建与发布诊断日志；分析结论报告保留在仓库内
- [ ] 内部台账不在索引也不在历史：签名材料台账、私有远端台账，以及文档中引用它们的段落
- [ ] 安全目录按 ADR-0011 改名为发布目录，只留发布流程、工具固定版本与第三方来源台账，内容不含内部台账
- [ ] 忽略规则统一为根级一套：构建缓存、Gradle/NDK 产物、APK/AAB、字体与工具链下载物、设备配置、受限目录都覆盖；结果是合并后的规则集，不是四层旧规则叠加
- [ ] fresh clone 后 `git status` 干净，跟踪内容体积与合并后规模相符（约 21 MB，最大单文件 5 MB 以内）
- [ ] 排除结果可复核：重复跑同一组命令即可证明上述各类在索引与历史中零命中
- [ ] 历史 ADR、历史工单与历史评审报告按 ADR-0013 决定 4 保留原文，不随改名改写

## Comments

2026-10-01 建单。这一步机械但触面广：改名要一路改到构建脚本里的路径，裁剪要按 ADR-0012 的"产品 + 设计 + 可复现的结论"重新划一遍仓库内容，两边都容易出现"改了一半"。

边界的写法是本单的关键：目录名、crate 包名、模块名改；`.so` 文件名、`Fable*` 类名、`applicationId` 派生的一切不改。越过这条线就会碰到 ADR-0013 冻结的应用身份。
