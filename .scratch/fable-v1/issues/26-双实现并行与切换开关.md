**4. 踩过的坑与解法**

- 坑 A（退出描述被吞）：初版 handleSessionExit 加了"!isRunning() 则 return"守卫，但 Java/Rust 后端都在
  onExit 投递前已把状态置为已退出 → 描述/通知永不触发。解法：去守卫，退出回调单次投递
  （Java waiter 单发；Rust session_closed 由 mExited 防重）。
- 坑 B（close 后事件被吞）：Rust close() 初版置 mClosed 后过滤所有事件 → session_closed 到不了 onExit。
  解法：只过滤 close 后的 output_chunk；session_closed 必须照常投递；close 只置 mClosed + sessionClose，
  不提前置 running=false（与 Java SIGKILL 语义对齐：退出描述仍正常显示）。
- 坑 C（包可见性）：ByteQueue 与 JNI 原为 terminal 包私有，缝在 .session 包 → 改 public
  （内部工具，仅缝内使用，已注释说明）。
- 坑 D（isRunning 语义差）：旧实现 spawn 前（pid=0）isRunning()==true，新实现 mFableSession==null → false；
  影响窗口极小（attach 后立刻 updateSize 初始化），行为更安全，记录不修。
- 坑 E（JVM 测试无法加载 .so / Termux 原生 JNI）：缝接线用 FakeSession 驱动断言；
  Java/Rust 真后端由构建产物校验 + 真机验收覆盖（同工单 15 模式）。

2026-08-11 真机反馈修复（Rust 模式 bash 登录缺失）：

**1. 根因（argv0 约定不一致）**

- Java 会话层 args[0] 是 argv0 名（登录 shell 为 "-bash"；JNI C 用 execvp(cmd, argv) 消费，
  bash 见 argv[0][0]=='-' 才读 profile）；libfable-session（工单 25）的 args 是**真实参数**
  （探针传 "--login" 同形）。
- Rust 模式把 "-bash" 当真实参数传给 bash → bash 收到非法参数（找不到脚本 "-bash"）→
  shell 未启动，profile 自然不加载（现象 = "没有 bash 登录"）。
- 工单 25 探针未暴露：探针 args={"--login"} 是真实参数形态，argv[0]=shell 路径本就不带
  '-'（非登录形态），但 --login 等价登录，自检只断言命令执行/事件，未断言 $0 或 profile。

**2. 修复**

- 缝内翻译：`RustPtySession.translateArgs`（纯静态，JVM 可测）——登录 argv0
  （args[0][0]=='-'）→ 显式 "--login"（bash/zsh/fish 等价语义）；非登录 argv0
  （failsafe 的 "sh"）→ 丢弃；其余参数原样保留。JavaFableSession 不变（Java C 本就正确）。
- 新增 `RustPtySessionArgsTest` 5 项：登录/非登录/带参数/空。
- 已知差异（对工单 27 的口径）：Rust 模式 $0 = shell 全路径（Java 模式 $0="-bash"）；
  bash login_shell 选项与 profile 加载两者等价。若 27 对比要求 $0 完全一致，
  需给 portable-pty 0.9.0 加 argv0 支持（本地 patch 约 15 行，列为 backlog 选项）。
