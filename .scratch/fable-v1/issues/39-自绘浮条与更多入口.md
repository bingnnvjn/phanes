### 1. 实施前的一处定案改判（用户拍板）

用户复查后明确：想要的是 <厂商 ROM>（HyperOS）原生选择工具栏观感，而此前"原生"路径给出的其实是 AOSP/Material 画法，并非该 ROM 样式；若原生不可行，则要一个**自制版、且样式有接口便于后续轻松改**（当前只做样本、先让功能可用，后续可能整体重置 UI）。

核对结论：**原生不可行**。App 主题是 `Theme.MaterialComponents`（AppCompat），系统 `ActionMode` 的悬浮工具栏只能按 AOSP/Material 画法渲染，拿不到 ROM 皮肤；且悬浮 ActionMode（`TYPE_FLOATING`）正是工单 04 第十二轮定位的 SurfaceView「选择空白」根因。故按用户授权走自制版 + 样式接口。

### 2. 实现方式

- **浮条**：`PopupWindow` 自绘（`TextSelectionActionBar`），仅复制/粘贴两项；窗口类型沿用选择手柄的 `TYPE_APPLICATION_SUB_PANEL`（与工单 04 已验证的安全类别一致，不引入悬浮 ActionMode）。定位默认贴选区上方居中，上方放不下落下方，水平/垂直夹在视口内。
- **移除系统 ActionMode**：选择生命周期、手柄、浮条全部自管；`ACTION_COPY/ACTION_PASTE/ACTION_MORE` 与 `text_selection_more` 资源（中英）一并删除。
- **样式接口**：`TextSelectionBarStyleProvider`（浮条：底色/圆角/字号/内外边距/抬升/间距等）与 `TextSelectionHandleStyleProvider`（手柄：左右 drawable + 热点/触摸偏移比例）为唯一样式来源，默认实现即当前样本；`TerminalView` 暴露两个可替换字段。后续换皮只替换 provider，不动交互代码。
- **「更多」入口**：抽屉顶部新增按钮（与设置齿轮并列，`ic_more` 三点图标）；`FableMorePanel` 为其下拉浮层（锚定按钮下方），六项动作 = 新会话 / 关闭 / 重命名 / 主题 / 字号 / 设置页。主题就地三选一（跟随系统/浅色/深色，写 `KEY_FABLE_THEME_MODE` 并重建，与设置页同源）；字号就地滑杆（8–24 dp，滑动即生效并持久化，取消还原原值）。
- **防御保持**：长按 300ms 防抖保留；手柄拖动经 `onHandleDragStart/End`（`CursorController` 接口）收起/重显浮条；选择态下 BACK 由 `TerminalView.onKeyDown` 消费，`FableActivity.onBackPressed` 再兜底一次；`FableTerminalView` 的 watchdog / forceRender / surface 重建防御未改动。
- **连带补偿**：「更多…」从选择菜单拆出后，右键上下文菜单的「分享选中文本」失去留存来源，改由 `onCreateContextMenu` 打开前留存当前选区（`captureSelectedTextForContextMenu`）。

### 4. 坑与解法

- **原生 ROM 观感不可达**：根因是 AppCompat 主题；且悬浮 ActionMode 与工单 04 已知 bug 相冲。→ 与用户确认后改自制版（见上）。
- **移除 ActionMode 的连带面**：BACK、长按防抖、手柄拖动隐藏工具条原本都由 ActionMode 提供，需逐条替代（见实现方式"防御保持"）；漏一条即行为回归。
- **构建脚本 shebang**：本机 `/usr/bin/env` 不存在，`./gradlew` 直接执行报 bad interpreter；用 `sh gradlew` 或 `sh ./build-and-verify.sh` 的等价命令绕过（既有环境问题，非本单引入）。
- **偶发测试**：全量 `:app:testDebugUnitTest` 曾出现一次 `FablePreferencesDataStoreTest` 失败（Robolectric + JDK 25，报 "Main looper has queued unexecuted runnables"），单独重跑与全量重跑均通过，属既有偶发，与本单无关。

### 5. 结论写回

- 定案落地并**扩大了一层**：浮条与手柄的样式都收口到可替换 provider，超出原单"仿一张截图"的诉求，直接服务于用户"后续整体重置 UI"的计划。
- **遗留（转工单 40 真机，非本单可证）**：① 浮条/手柄与 <厂商 ROM> 的观感差距——手柄本轮**未做视觉改动**，仅抽出了接口与热点换算，等真机截图或 UI 重置时定；② 无 ActionMode 后 BACK 键（含焦点丢失路径）、选择态与浮条在滚动/resize 下的重定位需真机复验；③ 浮条锚点改用真实选区矩形（旧 ActionMode 的 `selY1-1` + 手柄高度偏移是喂系统工具条的近似，已弃用），真机确认是否贴合。
- **对工单 40 的回归清单输入**（新增项）：长按选择→浮条出现且仅两项；复制/粘贴行为；拖动手柄收起浮条、松手重显；滚动/缩放时浮条跟随；选择态按 BACK 只收起选择不退出；抽屉「更多」六项动作——新会话、关闭、重命名、主题三选一即时生效并持久化、字号滑杆即时生效并持久化、设置页跳转；无当前会话时关闭/重命名禁用；右键上下文菜单「分享选中文本」在选区存在时仍可用。
