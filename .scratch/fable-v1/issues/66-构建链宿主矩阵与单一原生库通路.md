# 66 — 构建链宿主矩阵与单一原生库通路

**What to build:** 把"APK 里那四个原生库从哪里来"固定成一条明确、可复现的通路。现在这条路依赖设备上手工造的假 NDK：AGP 9 下产物进不了 APK，第二个设备（x86_64 电脑）的步骤在仓库里也没有记录。本单交付四样东西：宿主支持矩阵（写进文档）、一个仓库内的原生库生成脚本、真实的产物 ABI 范围、能拦住缺库的构建校验。修完，工单 65 的验证与推送才有前置条件。

### 坑

- **旧 `liblocal-socket.so` 是个坏库。** 假 NDK 的 shim 用 `clang`（C 驱动）编 C++ 源码，
  不链接 libc++：老库有 76 个 `std::__ndk1::*` 未定义符号、`NEEDED` 里没有 STL 依赖，
  一旦被 `System.loadLibrary("local-socket")` 加载就会在符号解析阶段失败。新通路改为
  运行时 `c++_shared`，并把 `libc++_shared.so` 一起打进 APK。Termux 没有静态 libc++
  （`libc++_shared.so` + `libc++experimental.a` 之外没有 `libc++_static.a`），所以两条宿主
  分支统一走 shared，而不是原 `Application.mk` 写的 `c++_static`。
- **`.incbin` 相对工作目录解析。** `termux-bootstrap-zip.S` 里 `.incbin "bootstrap-aarch64.zip"`
  是相对汇编器 CWD 找文件；编译必须在 `android/app/src/main/cpp/` 内执行（脚本已 `cd`）。
- **Termux clang 会注入 RUNPATH。** aarch64 宿主链接出的 `.so` 带
  `RUNPATH=/data/data/com.termux/files/usr/bin/../../usr/lib`（clang spec 注入，试过
  `-Wl,-rpath,`/`$ORIGIN` 都只能追加、不能去掉；旧库也有同样一条）。`.so` 不入库，
  Android 加载时会跳过不存在的路径，不影响加载；要去掉需要额外引入 `patchelf`，
  不值当。
- **跨目录构建不逐字节可复现。** 同一提交在 fresh clone 里编出的 `libfable-render.so`
  是 11,304,488 B（`d588b855…`），工作区里是 11,304,480 B（`befecd65…`）；差异来自
  Rust 二进制里嵌入的源码绝对路径。工单只要求可复现通路，不要求跨路径同哈希。
- **Apple 字体下载这次没成功。** `fetch-emoji-fonts.sh` 走 `ghfast.top` 拉 60.9 MB 的原始
  ttc，本机实测 ~130 KB/s 且中途 `curl: (56) Recv failure`。fresh clone 用的字体是从工作区
  已核验副本复制的（sha256 `6f6ad8b9…` 与来源表一致），不是脚本下载成功。工单 65 当次
  下载是通的；这是网络问题，不是通路问题。
- **假 NDK 目录留着也不会再被用。** `ndkVersion` 与 `ndkBuild` 声明都删了，设备上
  `$HOME/android-sdk/ndk/22.1.7171670` 那个 shim 目录已成为死配置（本单没删设备配置，
  留给用户决定）。
