## 背景（为什么有这个工单）

改名 com.termux → com.gph.fable 后，APK 内嵌的官方 bootstrap 硬编码 `/data/data/com.termux/files/usr`（632/3490 个文件，含 bash/dash/dpkg/apt 的编译期前缀、第二阶段脚本、SYMLINKS.txt），新 App 的 $PREFIX 是 `/data/data/com.gph.fable/files/usr`，且新 UID 读不到旧目录 → 真机 Bootstrap Error。官方确认：改包名必须用新前缀重建全部包并重新生成 bootstrap（termux-app issue #3973 / #1059 / #2160）。

## 任务（按顺序）

1. **建公开仓库** `bingnnvjn/fable-bootstrap`：`gh` 已登录（账号 bingnnvjn，token 有 repo + workflow 权限），直连 GitHub 已通。GitHub 不允许把公开仓库 fork 成私有/独立公开副本没有 fork 关系，所以我们做独立副本：浅克隆 termux/termux-packages（`--depth 1`）→ 推到新仓库（提交历史干净）。
2. **研究 termux-packages 标准流程**：`TERMUX_PREFIX` 定义位置、`build-package.sh`、`generate-bootstraps.sh`、bootstrap 包清单、本地 apt 仓库要求；把 `TERMUX_PREFIX` 改为 `/data/data/com.gph.fable/files/usr`。
3. **编写 GitHub Actions workflow**（ubuntu runner）：构建基础包 → 生成 bootstrap zip（+ 本地 apt 仓库或等价物），配缓存、可重跑。
4. **落实安全清单**（用户明确要求，公开仓库必须全过）：
   - 任何 token / keystore / 密码不进仓库；workflow 只用 `${{ secrets.GITHUB_TOKEN }}`，`permissions` 最小化（`contents: read`）
   - 不用 `pull_request_target`；不打印含密钥的 debug 日志
   - 提交前检查历史无敏感文件；不提交本地路径、个人文档、交接文档
   - main 分支保护如可配则配
5. **触发 CI，下载 aarch64 bootstrap zip，验证**：
   - zip 完整性（`unzip -t`）
   - `/data/data/com.termux` 出现次数 = 0（SYMLINKS.txt、第二阶段脚本、bin/bash、bin/dpkg、bin/apt 抽查）
   - 记录变体（apt-android-7）、bootstrap 版本/日期、包清单摘要
6. **交付写回工单 06 `## Comments`**：产物 URL + sha256 + 集成 fable-app 步骤（替换 `app/src/main/cpp/bootstrap-aarch64.zip` → 重编 libtermux-bootstrap.so → 重建 APK → 真机验收）。
