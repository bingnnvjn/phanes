## 1. 共识（已达成；启动优化时不得推翻，除非用户明确改口）

- **性能 = 流畅度 + 资源效率**。内存占用是性能硬指标，与动画流畅同级。
- **目标设备档：8GB**。不按 4GB（不现实，会逼伤筋动骨的取舍）；不按 12GB
  （开发不能拿最好的配置当基准；12GB 是 8GB 优化后的自然覆盖）。
- **度量哲学：预算制，不设绝对数字**。稳态目标约 1GB 以内；峰值不允许
  「创建尖峰」这类纯浪费；能省 10MB 必做、5MB 选择性做——吹毛求疵但务实。
- **红线：流畅优先、功能不减**。优化对象是浪费（分配时机、缓冲策略、过度分配），
  不是功能或体验。
- **好公民**：<厂商 ROM> 系统占用高（3–4.5GB 常见）且调度激进，改不了系统就改自己——
  响应内存回收、后台瘦身、低泄漏、不抢资源。App 是个人自用，不是超级 App。
- **时机：Kotlin 壳重构（终态，ADR-0001/0003）之后**开专门性能窗口；此前不拆工单
  （避免与重构冲突返工）。已按用户决定记录为 backlog 一行，不建工单。

## 3. 发散方向池（未评估、未立项；窗口开启后按需取用）

### A. 测量先行

- Debug 内存仪表：native / Dalvik / Graphics 分块实时显示，细化到每会话占用。
- N 会话内存曲线回归基准（仿 `verify.sh`）：每次构建自动跑，防回归。
- 第一个调查项：尖峰时刻 dumpsys meminfo / malloc profile，坐实尖峰归属。

### B. 渲染 / 核心层

- 图集按需生长 + LRU 淘汰（不默认 4096 方阵）；灰度用 R8、彩色按需分配。
- wgpu staging 缓冲复用池；静止画面降帧。
- scrollback 上限按内存档自适应（8GB 档低、12GB 档高）。

### C. 多开会话轻量化（方向最大的一个）

- 后台会话 headless：无核心、无渲染，只留事件流——契合 ADR-0008 事件流，
  Agent 订阅的本来就是事件；切回时恢复视口。
- scrollback 落盘 / 分页，内存只留游标与事件。
- 创建尖峰摊平：延迟分配、预热、核心池复用（切换时 detach 不销毁）。

### D. 系统好邻居

- onTrimMemory 分级释放；冷启动错峰加载（字体/图集）；
- 按 memory class 自适应档位；压力下降级提示而非崩溃。

### E. 更发散

- 输出流压缩进环形缓冲；mmap 文件映射换内存；核心池迁移；低档位滚动缓冲分页。
