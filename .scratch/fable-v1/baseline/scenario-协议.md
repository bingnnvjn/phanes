# fable-v1/23 压力场景协议（12 分钟 · 可重复）

> 本协议是工单 27「Rust vs Java 同场景对比」的口径来源：27 重跑时必须使用同一脚本、
> 同一参数、同一操作节奏，指标表逐项对齐。只采集与记录，不改任何功能。

## 场景构成

- **4 会话并行**：Fable 主终端开 4 个会话（抽屉 → 新会话），编号 s1~s4。
- **长输出（seq 语义）**：每会话运行确定性顺序流
  `sN_r001_000001 … sN_r090_005000`（90 轮 × 5000 行，轮间 7s，合计 450,000 行，
  约 12 分钟）。每 1000 行的行尾为 `_00X000`（标记行），用于目视检查。
  输出同时 `tee` 到 `current/sN.txt`——文件内容 = 写入该会话 PTY 的同一字节流，
  是「无丢失/无乱序」的程序化真值。
- **频繁切换/滚动**：每 3 分钟一个周期，含 6 次会话切换、12 次滚动动作（见下表）。
- **复制粘贴**：每周期 2 次复制 + 2 次粘贴，跨会话进行（s1→s2、s3→s4）。
- **总时长 ≥10 分钟**：4 个周期共 12 分钟；任何会话不提前结束。

## 前置

1. 已安装验收 APK（见 README 前提）；Fable 终端可开 4 会话、可长按选择复制/粘贴。
2. 运行 `start-run.sh`（准备 run 目录 + 启动内存采样器）。
3. 4 个会话分别后台运行 `run-session.sh s1 &` … `s4 &`，等待首个输出出现。
4. 记下当前时间（报告起止时刻用）。

> 执行方式二选一，口径相同：
> - 人工：按下方节奏操作，异常时刻人工记录；
> - adb 自动化：`adb-drive.sh prep → stress → finish`，节奏由驱动实现
>   （每周期 4 次切换+滚动对、2 复制 2 粘贴、周期末截图；与人工表等价）。

## 每 3 分钟周期（重复 4 次 = 12 分钟）

| 时间段 | 操作 | 记录项 |
| --- | --- | --- |
| 0:00–0:45 | **滚动清扫**：按 s1→s2→s3→s4 依次切换（每 15s 一次）；每次切换后向上滚动约 1 屏，目视检查数字连续性（相邻行差 1、`_00X000` 标记按 1000 递增出现），再滚回底部 | 切换延迟 >1s 次数；滚动冻结/明显掉帧次数（时刻） |
| 0:45–1:45 | **复制粘贴**：在 s1 长按选中 2 行 → 复制；切到 s2 → 长按 → 粘贴。在 s3 复制 → 切 s4 → 粘贴（共 2 复制 + 2 粘贴） | 每步响应 >1s 次数；粘贴文本是否出现在目标会话（是/否 + 时刻） |
| 1:45–3:00 | **持续输出观察**：停在 s4 观察输出滚动流畅度（无冻结/跳变）；在 s1 快速上下滚动 2 屏 × 1 次；3:00 整截图 | 冻结 >1s 次数（时刻）；截图文件名 |

每周期统计：6 次切换 / 12 次滚动动作 / 2 复制 / 2 粘贴 / 1 截图。
4 周期总计：24 次切换 / 48 次滚动动作 / 8 复制 / 8 粘贴 / 4 张定时截图。

## 指标定义（报告用，口径唯一）

| 指标 | 操作性定义 |
| --- | --- |
| 崩溃 | App 进程退出：所有终端消失 / <厂商 ROM>「已停止」提示 / `mem-samples.tsv` 中断且 `sampler.log` 无 STOP |
| ANR | <厂商 ROM>「应用无响应」对话框出现 |
| 卡顿 | 界面冻结或操作响应 >1s（含切换后画面空白 >1s）；滚动掉帧单独记，不算卡顿 |
| 输出完整性 | ① 程序化：`verify.sh` 对 4 份 `sN.txt` 的 sha256 与期望流逐字节一致、行数=450000、首末行正确；② 目视：滚动中相邻行差 1、标记行按 1000 递增、各会话结束最后一行=`sN_r090_005000` |
| 内存 | 5s 间隔采样 app 同 UID 进程 VmRSS（PSS 尽力），报告单进程峰值与合计峰值 |
| surface 稳定性 | `fable-render-debug.log.txt` 运行窗口内 `surfaceDestroyed` / `autoRecreateSurface` / `scheduleAutoRecreate` 计数（verify 输出） |
