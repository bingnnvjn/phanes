### 假 NDK（缺陷现场，仓库外设备配置）

- 位置：`$HOME/android-sdk/ndk/21.4.7075529/`、`$HOME/android-sdk/ndk/22.1.7171670/`
- `ndk-build` 是 2032 B 的 shell 脚本；`source.properties`、`meta/abis.json`、`meta/platforms.json` 手写；`prebuilt/` 为空；`toolchains/llvm/prebuilt/*/bin/` 只有两个包装脚本；`libc++_shared.so` 从 Termux 拷入
- 它忽略 AGP 的 `-n`，AGP 的 `app/build/.cxx/Debug/<hash>/<abi>/android_gradle_build.json` 得到 `"libraries": {}`，产物不进 merge

### 宿主矩阵的核实来源

`https://dl.google.com/android/repository/repository2-3.xml`（2026-10-02 拉取）。按 `<host-os>`+`<host-arch>` 统计：linux x64 = 64，linux aarch64 = 0，macosx x64 = 63，macosx aarch64 = 61，windows x64 = 64。结论：官方没有 Linux aarch64 的 NDK。

## 已定决策（不再讨论）

- 一条通路：所有宿主都用仓库内脚本生成四个原生库并放进打包输入目录；不再依赖 AGP 的 ndkBuild 产物
- 宿主矩阵：x86_64 类宿主用官方 NDK 的 clang；Linux aarch64 用 Termux clang + ndk-sysroot；两者同一个脚本、同一组参数
- 产物 ABI 收窄到项目目标设备实际支持的 ABI（当前目标 = aarch64）
- 应用身份冻结，`applicationId` = `com.gph.fable`（ADR-0013）
- 构建输入不入库、操作记录不入库、目录用角色名（AGENTS.md 三条硬规则）

## 红线

- 不推送、不建远端仓库、不改可见性、不建 tag/release（推送是工单 65 的事）

## 已知坑

- AGP 9 用 `ndk-build ... -n` 建模型。任何"让 AGP 满意"的替身都必须实现 dry-run 语义，否则产物静默丢失。
- `jniLibs` 里的旧文件会掩盖缺库。验证必须从**清空 jniLibs 的 fresh clone** 开始。
- GitHub 直连常失败。`scripts/rust-supply-chain-gate.sh` 支持 `FABLE_GITHUB_MIRROR`；2026-10-02 实测 `https://ghproxy.net/` 可用，`https://ghfast.top/` 不可用。
- 本机文件系统慢：`du`、`git ls-files`、`sha256sum` 大文件都要留时间。
- 真机验收要确认 `.so` 能加载，不只是存在（TLS 对齐一类问题历史上出现过）。
