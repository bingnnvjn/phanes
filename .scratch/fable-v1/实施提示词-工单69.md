## 已定决策（不再讨论，来自决策窗口 12）

1. 新 module 放 `renderer/src/core.rs`；两个对象 `Terminal`（持核心连接）与 `Screen`（持渲染状态）；短名，不加前缀。
2. `Screen::update` 收 `&mut Terminal`——核心要求 update 时独占实例，用 `&mut` 让编译器挡住同时读写。
3. 出错：open / feed / resize / scroll / update / snapshot 返回 `Result`；text / word_at / word_bounds_at / title / mode_* 返回普通值，失败 `debug_assert` 加日志。module 不写日志。
4. `Rgb`、`Palette`、`Cell`、`Snapshot`、`OverlayRange` 搬进新 module，不留旧 import 路径。
5. 模块顶部注释写清两件事：为什么分两个对象、"读之前必须先 update"；并写明业务代码只走本 module，不直接调 ffi。
6. 加一个"读完一次"的入口：给字节返回快照，内部是 open → feed → update → snapshot 的串联，只是方便一次性调用方，不额外实现别的路径。
7. 测试只覆盖抽出来的纯逻辑（取词边界、去行尾空白、续行判断）。
8. `CONTEXT.md` 不动（已有"核心""渲染状态"两个词），不开 ADR（改动便宜、不算难逆）。

## 已知坑

- `TerminalEvents` 是挂在 terminal 的 userdata 上的裸指针，`RendererCore` 持有 box 保证地址稳定。搬的时候它必须跟着 `Terminal` 走，不能留在 `RendererCore`，否则回调写到一个已经释放的地址。
- `GpuRuntime` 是懒加载（`render_android.rs:4398`、`4424`、`4827`），不带 surface 时不会建 Vulkan 设备。所以"读取不需要 GPU"这句话成立，但内容查询目前仍要经渲染线程 mailbox，本单不改这一点。
- 12 处 `let _ =` 里有 `update` 和 `resize`。搬的时候按新语义处理，不要原样搬过去继续吞。
- `main.rs` 里有 4 处几乎是同一段建连接代码，但每处场景不同（滚动 / resize / UI 状态 / 主验证）。搬的时候分清哪些能换成"读完一次"的入口，哪些必须用两个对象分步调用。
- 删除诊断程序前，确认 `renderer/Cargo.toml` 没有声明 `[[example]]` 或 `default-run`（2026-10-04 核实：都没有）；删文件即可，不会有配置残留。
- 本机文件系统慢：`wc`、`git ls-files` 这类命令在仓库上要留时间。
