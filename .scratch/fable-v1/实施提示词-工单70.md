## 本单最要紧的一条（工单 35 的教训）

**行为等价迁移必须逐对比较 Java 原件。** 编译器、单测、真机都不会报的静默漂移，全在逐行比对里才看得见。工单 35 就是这样抓出 5 个真错的。

对照方法：迁移前的原件用 `git show <该文件最后一个 Java 版本所在提交>:<路径>` 取；本单只需对比同名 `.java` → `.kt`。

工单 35 实际踩到的漂移类型（本单重点自查同类）：

- 枚举取值：Kotlin `enum.name`（内建名，大写）vs Java 自定义 `getName()`（契约值）
- null 处理：`x?.toString()` 会不导出，Java `String.valueOf(x)` 导出字面量 `"null"`
- 集合 API：`listOfNotNull` vs `Collections.singletonList`；`sortedWith`（不改写入参）vs `Collections.sort`（原地）
- 空白判定：Kotlin `Char.isWhitespace()` 把 NBSP 等 SpaceChar 也算空白，`Character.isWhitespace(c)` 不算
- 区域相关：`uppercase()`（无区域）vs `toUpperCase()`（默认区域）
- 锁：Java `synchronized` 迁移后必须显式 `@Synchronized`，否则并发契约悄悄消失
